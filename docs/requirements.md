# 散歩アプリ 要件定義書

## 1. 目的

目的地へ向かう安心感を保ちながら、知らない道への寄り道を楽しめる散歩体験を提供する。

本アプリは最短経路への誘導を主目的としない。ユーザーには目的地までの距離と方角という最低限の手掛かりを示し、経路の選択を委ねる。歩いた場所だけが地図上で明らかになる表現と、東京都のオープンデータを利用したスポット情報により、探索する楽しさを生み出す。

## 2. 想定ユーザー（ペルソナ）

- 散歩や寄り道が好きで、効率よりも発見を楽しみたい。
- 知らない道に興味はあるが、「この道に入ると目的地から遠ざかるのではないか」という不安がある。
- 地図やナビの指示どおりではなく、自分で道を選びたい。

## 3. 解決する課題

通常の地図・ナビアプリは目的地までの経路を先に見せるため、安心できる一方で、経路から外れることを失敗のように感じさせる。本アプリは次の方法でこの課題を解決する。

- 距離と方角を常に確認できるようにし、目的地を見失う不安を減らす。
- 未踏エリアを隠し、歩くことで地図が開ける探索体験を作る。
- 近くの寄り道候補を提示し、新しい道へ踏み出すきっかけを作る。
- 歩行ログ、距離、消費カロリーにより散歩の成果を振り返れるようにする。

## 4. MVPの範囲

### 対象に含める

1. 目的地の設定
2. 距離・方角モード
3. 踏破マップ（通過した場所のみ可視化）
4. オープンデータを利用した寄り道スポット表示
5. 歩行距離と推定消費カロリーの表示
6. 散歩中の位置ログの記録と散歩後の振り返り

### 対象に含めない

- 最速・最短ルートの検索およびターンバイターン案内
- SNS、ランキング、他ユーザーとのログ共有
- バックグラウンドでの常時記録の完全対応
- 健康管理サービスやウェアラブル端末との連携

最速ルート表示は将来機能とする。ただし、現在地から目的地までの距離と方角を算出できるデータ構造はMVPから保持する。

## 5. 主要な利用シナリオ

1. ユーザーが目的地を検索または地図上で指定する。
2. アプリが位置情報の利用許可を得て、散歩を開始する。
3. ユーザーは距離・方角モードで、目的地がおおよそどちらにあり、どれだけ離れているかを確認する。
4. ユーザーは気になる道や表示された寄り道スポットを目指して自由に歩く。
5. 踏破マップでは歩いた場所の周囲だけが見えるようになる。
6. アプリは移動経路、歩行距離、経過時間、推定消費カロリーを記録する。
7. ユーザーは目的地への到着時または任意の時点で散歩を終了し、結果を振り返る。

## 6. 機能要件

### FR-01 目的地設定

- ユーザーは地点検索または地図上の地点選択によって目的地を1件設定できる。
- 設定後、目的地の名称または住所を確認できる。
- 散歩開始前および散歩中に目的地を変更できる。
- 目的地を設定していない場合、散歩開始操作を無効化し、その理由を表示する。

### FR-02 散歩の開始・終了

- ユーザーは目的地設定後に散歩を開始できる。
- 記録中であることと経過時間を確認できる。
- ユーザーは任意の時点で散歩を終了できる。
- 目的地から一定範囲内に入った場合、到着した可能性を通知し、終了するか選択できる。
- MVPにおける到着判定の初期値は、目的地から半径50 m以内とする。

### FR-03 距離・方角モード

- 現在地から目的地までの直線距離を表示する。
- 目的地の方角を矢印と方位で表示する。
- 距離と方角は位置情報の更新に合わせて更新する。
- 表示する距離は経路距離ではなく直線距離であることを明示する。
- 端末のコンパス情報を利用できない場合は、北を基準とした方角表示に切り替える。

### FR-04 踏破マップ

- 散歩開始時の地図は、現在地付近および過去に通過した範囲を除いて、モザイク、霧、または同等のマスクで隠す。
- 記録した位置の周囲を通過済み範囲として徐々に可視化する。
- MVPにおける可視化範囲の初期値は、各位置情報を中心とする半径30 mとする。
- 通過済み範囲は散歩終了後もユーザー端末に保持し、次回以降の散歩に引き継ぐ。
- マスク表示中でも、現在地、目的地、寄り道スポット、アプリの操作UIは識別できる。
- 位置情報の精度が著しく低い点は踏破範囲の更新に使用しない。

### FR-05 寄り道スポット

- 東京都または都内自治体が公開するオープンデータから、散歩中に立ち寄れる地点を表示する。
- MVPでは、公園、文化施設、公衆トイレ、給水場所等から、入手可能性とライセンスを確認できた1種類以上を採用する。
- 現在地付近のスポットを踏破マップおよび一覧で確認できる。
- 各スポットについて、名称、カテゴリ、現在地からの直線距離、出典を表示する。
- スポットを選択すると、目的地を変更せずに、そのスポットのおおよその方向と距離を確認できる。
- データが取得できない場合も、目的地への距離・方角表示と歩行ログ記録は継続する。

### FR-06 歩行ログ

- 散歩中、取得時刻、緯度、経度、位置精度を時系列で記録する。
- ログから歩行距離、開始・終了時刻、所要時間を算出する。
- 散歩終了後、通過した軌跡と基本統計を確認できる。
- ユーザーは保存済みの散歩履歴を一覧表示し、個別に確認できる。
- 不自然な位置飛びや精度の低いデータを距離計算から除外する。

### FR-07 推定消費カロリー

- 散歩中および終了後に推定消費カロリーを表示する。
- 初回利用時または設定画面で体重を入力できる。
- 体重未入力時は標準体重を用いた参考値として表示する。
- 算出根拠が歩行距離、歩行時間、体重等による推定値であり、医療用途ではないことを明示する。
- 採用する計算式、係数、標準体重は実装時に記録し、画面から確認可能にする。

### FR-08 権限・エラー対応

- 位置情報を利用する目的を、OSの許可要求前に説明する。
- 位置情報が拒否または無効の場合、必要な設定と再試行方法を案内する。
- GPS信号が一時的に失われてもアプリを終了せず、最後の取得時刻を表示する。
- 通信障害時も取得済みの歩行ログを失わず、可能な範囲で記録を継続する。

## 7. 画面要件

| 画面 | 主な表示・操作 |
| --- | --- |
| 目的地設定 | 地点検索、地図から選択、選択地点の確認、散歩開始 |
| 距離・方角 | 方角矢印、方位、直線距離、経過時間、カロリー、踏破マップへの切替、終了 |
| 踏破マップ | 現在地、目的地、歩行軌跡、踏破済み範囲、未踏マスク、寄り道スポット |
| スポット詳細 | 名称、カテゴリ、距離、方角、出典 |
| 散歩結果 | 軌跡、歩行距離、所要時間、推定消費カロリー、立ち寄ったスポット |
| 履歴 | 過去の散歩一覧、個別結果への遷移、履歴削除 |
| 設定 | 体重、位置情報に関する説明、データ・ライセンス表示 |

## 8. データ要件

### 散歩記録

- 一意な散歩ID
- 目的地（名称、緯度、経度）
- 開始日時、終了日時
- 位置ログ（取得日時、緯度、経度、精度）
- 算出した歩行距離、所要時間、推定消費カロリー
- 立ち寄ったスポットID（判定する場合）

### オープンデータ

採用するデータセットごとに、次を記録する。

- データセット名、公開者、配布元URL
- 更新日または更新頻度
- 利用規約・ライセンスと必要なクレジット表記
- 対象地域、位置情報の形式、カテゴリ
- アプリへの取り込み・更新方法

データ選定では、東京都オープンデータカタログ等の一次配布元を優先し、位置座標が取得でき、再利用条件が明確で、散歩中に徒歩で立ち寄れることを必須条件とする。

## 9. 非機能要件

### プライバシー・安全性

- 位置ログは機微な個人情報として扱い、MVPでは原則として端末内に保存する。
- サーバーへ送信する場合は、送信目的、保存期間、削除方法を事前に定義し、ユーザーの同意を得る。
- ユーザーは自分の散歩履歴および蓄積した踏破データを削除できる。
- ログやエラー情報に正確な位置情報や体重を不用意に出力しない。
- 歩行中の画面注視を促さない簡潔な表示とし、危険区域へ誘導する表現を避ける。

### 性能・可用性

- 距離・方角表示は、新しい有効な位置情報を受信してから原則1秒以内に更新する。
- 位置取得間隔と精度を調整し、一般的なスマートフォンで60分以上の散歩に利用できることを目標とする。
- 通信が一時的に切断されても、散歩中の位置ログを端末内に保持する。

### 対応環境・アクセシビリティ

- MVPは位置情報と方位センサーを利用できるスマートフォン向けWebアプリを対象とする。
- 最新の主要なモバイルブラウザのうち、開発時に定めた対象ブラウザで動作確認する。
- 方角や状態を色だけで区別せず、文字、形状、アイコンを併用する。
- 屋外で読めるコントラストと十分なタップ領域を確保する。

## 10. 受入条件（MVP）

- 目的地を設定し、散歩を開始・終了できる。
- 位置情報を更新すると、目的地までの直線距離と方角が追従する。
- 未踏エリアが隠れ、移動した場所の周囲だけが可視化される。
- 採用したオープンデータ由来のスポットが、出典付きで表示される。
- 10分以上のテスト歩行後、軌跡、距離、所要時間、推定消費カロリーを確認できる。
- 一時的な通信断の後も、端末内の歩行ログが失われない。
- 位置情報を拒否した場合に、アプリが停止せず案内を表示する。
- 履歴および踏破データをユーザー操作で削除できる。

## 11. 成功指標（仮説検証）

- テストユーザーが、地図による経路案内なしで目的地へ到達できる割合
- 「知らない道へ踏み出す不安が減った」と回答したユーザーの割合
- 1回の散歩で通常の想定経路から寄り道した回数または距離
- 寄り道スポットの詳細表示率および接近率
- 散歩完了率と、距離・方角表示を確認した回数

## 12. 将来要件

### 最速ルート表示

- ユーザーが安心を優先したい場合に限り、現在地から目的地までの最速または最短ルートを表示できる。
- 通常の探索体験を損なわないよう、既定では非表示とし、明示的な操作で表示する。
- ルート表示後も歩行ログと踏破マップを継続できる。
- 利用する経路探索サービス、料金、利用規約、道路種別および安全性は別途検討する。

## 13. 未決事項

- MVPで採用する東京都オープンデータの具体的なデータセットとカテゴリ
- 目的地検索および地図タイルの提供元、料金、利用規約、クレジット表記
- Webアプリでのバックグラウンド位置取得の扱いと、画面ロック中の仕様
- 踏破済み範囲を端末間で同期するか
- 到着判定半径、踏破範囲、位置精度の除外基準の実地検証
- 消費カロリー計算式および標準体重の決定
- 「立ち寄ったスポット」の判定をMVPに含めるか
- 隠れた地図上でスポットをどこまで見せるか（すべて表示、近距離のみ、存在だけを示す等）
