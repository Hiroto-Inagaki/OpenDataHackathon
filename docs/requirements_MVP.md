# 散歩アプリ MVP 要件定義書

## 1. 目的

目的地までの最短経路を案内するのではなく、ユーザー自身が道を選びながら散歩できる体験を提供する。

MVPでは、目的地までの**距離と方角という最低限の手掛かり**だけを提示し、具体的な経路は表示しない。

これにより、目的地までの方向を確認できる状態を維持しながら、ユーザーが任意の経路を選択できる散歩体験を実現する。

---

## 2. MVPの目的

MVPでは、以下のシステム機能を実装し、距離・方角による目的地案内が成立することを検証する。

- 目的地を1件設定できること
- 現在地を取得できること
- 現在地から目的地までの直線距離を算出できること
- 現在地から目的地への方角を算出・表示できること
- 具体的な経路を表示せずに案内できること
- 散歩の開始・終了状態を管理できること

---

# 3. MVPスコープ

## 3.1 MVPで実装する機能

| ID | 機能 | MVP |
| --- | --- | --- |
| FR-01 | 目的地設定 | 実装 |
| FR-02 | 散歩の開始・終了 | 実装 |
| FR-03 | 距離・方角モード | 実装 |
| FR-04 | 踏破マップ | 対象外 |
| FR-05 | 寄り道スポット | 対象外 |
| FR-06 | 歩行ログ | 対象外 |
| FR-07 | 推定消費カロリー | 対象外 |

MVPでは、以下の処理を実装対象とする。

1. 目的地を設定する
2. 散歩を開始する
3. 現在地を取得する
4. 現在地と目的地から距離を算出する
5. 現在地と目的地から方角を算出する
6. 距離・方角を案内画面に表示する
7. 散歩を終了する

## 3.2 MVP対象外

以下はMVPでは実装しない。

- 最速・最短ルート検索
- ターンバイターンによる経路案内
- 踏破マップ
- オープンデータによる寄り道スポット表示
- 歩行軌跡の永続保存
- 散歩履歴
- 歩行距離の履歴保存
- 推定消費カロリー
- SNS・ランキング
- 他ユーザーとのデータ共有
- ウェアラブル端末連携
- ユーザーアカウント
- サーバーへの散歩データ同期
- バックグラウンドでの常時位置記録

# 4. 画面要件

MVPでは以下の2画面を実装する。

## 4.1 目的地設定画面

### 表示項目

- 地図
- 地点検索入力欄
- 検索結果
- 選択した地点
- 目的地名称
- 目的地住所
- 「散歩を開始」ボタン

### 操作

- 地点名・住所等による目的地検索
- 検索結果からの目的地選択
- 地図上の地点選択
- 設定済み目的地の変更
- 散歩開始

### 状態

#### 目的地未設定

- 「散歩を開始」ボタンを無効化する。
- 目的地が未設定であることを表示する。

#### 目的地設定済み

- 選択した地点を地図上に表示する。
- 目的地名称または住所を表示する。
- 目的地の緯度・経度を保持する。
- 「散歩を開始」ボタンを有効化する。

---

## 4.2 案内画面

### 表示項目

- 目的地までの直線距離
- 目的地方向を示す矢印
- 方位
- 経過時間
- 位置情報の取得状態
- 「散歩を終了」ボタン

### 表示しない情報

以下は案内画面に表示しない。

- 最短経路
- 推奨経路
- 道路上のルート
- ターンバイターン案内
- 次に曲がる方向
- 経路距離

---

# 5. 機能要件

## FR-01 目的地設定

### FR-01-01 目的地検索

- ユーザーが地点名または住所等を入力して検索できる。
- 検索結果を一覧表示できる。
- 検索結果には、目的地名称および位置情報を含める。
- 検索結果から1件を選択できる。

### FR-01-02 地図上からの地点選択

- 地図上の任意の地点を選択できる。
- 選択した地点の緯度・経度を取得できる。
- 取得した地点を目的地として設定できる。

### FR-01-03 目的地情報

目的地として以下の情報を保持する。

- 目的地ID
- 目的地名称
- 住所
- 緯度
- 経度

### FR-01-04 目的地変更

- 散歩開始前に目的地を変更できる。
- 新しい目的地を設定した場合、以前の目的地を上書きする。
- MVPでは目的地を複数保持しない。

### FR-01-05 散歩開始制御

- 目的地が設定されていない場合、散歩を開始できない。
- 目的地が設定されている場合、「散歩を開始」ボタンを有効化する。

---

## FR-02 散歩の開始・終了

### FR-02-01 散歩開始

散歩開始時に以下の処理を実行する。

1. 位置情報の利用権限を確認する。
2. 現在地を取得する。
3. 散歩状態を「実行中」に変更する。
4. 開始日時を取得する。
5. 案内画面へ遷移する。

### FR-02-02 散歩状態

散歩状態として以下を管理する。

- 未開始
- 実行中
- 終了

### FR-02-03 経過時間

- 散歩開始時刻を基準として経過時間を算出する。
- 案内画面に経過時間を表示する。
- 散歩終了時に経過時間の更新を停止する。

### FR-02-04 散歩終了

- ユーザーは任意のタイミングで散歩を終了できる。
- 終了操作時に確認ダイアログを表示する。
- 終了を確定した場合、散歩状態を「終了」に変更する。
- 案内画面を終了する。

### FR-02-05 到着判定

MVPでは自動到着判定を実装しない。

目的地から一定距離以内に入った場合の到着通知は、将来機能とする。

---

## FR-03 距離・方角モード

### FR-03-01 現在地取得

- 端末の位置情報APIを利用して現在地を取得する。
- 取得データとして以下を利用する。
    - 緯度
    - 経度
    - 取得時刻
    - 水平位置精度

### FR-03-02 距離算出

現在地と目的地の緯度・経度から2地点間の直線距離を算出する。

- 道路ネットワークは使用しない。
- 経路検索APIは使用しない。
- 距離の単位はmまたはkmとする。
- 表示単位および小数点以下の桁数は実装時に定義する。

### FR-03-03 方角算出

現在地から目的地への方位角を算出する。

基本表示方向は以下の8方位とする。

| 方位 | 角度 |
| --- | --- |
| N | 0° |
| NE | 45° |
| E | 90° |
| SE | 135° |
| S | 180° |
| SW | 225° |
| W | 270° |
| NW | 315° |

8方位への分類方法および角度表示の有無は実装時に定義する。

### FR-03-04 端末方位センサー

端末の方位センサーを利用可能な場合、端末の向きに応じて目的地方向の矢印を更新する。

方位センサーを利用できない場合は、地理的な北を基準とした方角を表示する。

### FR-03-05 更新

新しい有効な位置情報を取得した場合、以下を再計算する。

- 現在地
- 目的地までの距離
- 目的地までの方角

新しい位置情報を取得できない場合は、直前の算出結果を保持する。

### FR-03-06 位置精度

- 位置情報の水平精度を取得する。
- 精度が設定した閾値を超える場合、その位置情報を距離・方角の算出対象から除外する。
- 精度の閾値は実装時に決定する。

---

# 6. 画面遷移要件

MVPでは以下の画面遷移とする。

```
目的地設定画面
      │
      │ 目的地設定
      ▼
目的地設定画面
      │
      │ 散歩開始
      ▼
位置情報権限確認
      │
      ├── 許可
      │    ▼
      │  案内画面
      │
      └── 拒否
           ▼
       権限エラー表示
```

案内画面から散歩を終了した場合は、目的地設定画面へ戻る。

# 7. データ要件

## 7.1 目的地データ

| 項目 | 型の例 | 必須 |
| --- | --- | --- |
| destinationId | String | ○ |
| name | String | ○ |
| address | String | △ |
| latitude | Number | ○ |
| longitude | Number | ○ |

MVPでは目的地を1件のみ保持する。

---

## 7.2 セッションデータ

散歩中は以下の情報をメモリ上で保持する。

| 項目 | 内容 |
| --- | --- |
| status | 散歩状態 |
| startedAt | 開始日時 |
| currentLatitude | 現在地緯度 |
| currentLongitude | 現在地経度 |
| currentAccuracy | 現在地の精度 |
| currentLocationAt | 現在地取得日時 |
| distanceToDestination | 目的地までの直線距離 |
| bearingToDestination | 目的地への方位角 |

MVPでは、散歩終了後の位置情報・セッションデータを履歴として永続保存しない。

---

# 8. 距離・方角計算仕様

## 8.1 距離

入力：

- 現在地の緯度・経度
- 目的地の緯度・経度

出力：

- 2地点間の直線距離

計算方式は緯度・経度から地表面上の距離を算出できる方式とする。

実装方式としてHaversine formula等を利用できる。

## 8.2 方位角

入力：

- 現在地の緯度・経度
- 目的地の緯度・経度

出力：

- 現在地から目的地への方位角

方位角は北を0°として時計回りに増加する角度とする。

---

# 9. 位置情報要件

## 9.1 権限

- 位置情報を利用する目的をOSの権限要求前に表示する。
- 位置情報利用許可を取得できない場合、案内機能を開始しない。
- 権限拒否時には再試行方法またはOS設定への導線を表示する。

## 9.2 位置情報取得

- 散歩開始時に現在地を取得する。
- 散歩中は位置情報の更新を監視する。
- 新しい位置情報を取得するたびに距離・方角を再計算する。
- 取得間隔は端末のバッテリー消費と表示更新性能を考慮して設定する。

## 9.3 位置情報取得失敗

位置情報を取得できない場合は以下を行う。

- アプリを終了しない。
- 最後に正常取得した位置情報を保持する。
- 位置情報が更新されていないことを画面に表示する。

---

# 10. 方位センサー要件

- 端末が提供する方位センサーを利用する。
- センサー値から端末の向きを取得する。
- 端末の向きが変化した場合、目的地方向の矢印を更新する。
- センサーが利用できない場合は代替表示を行う。
- センサー利用に追加のブラウザ権限が必要な場合、その権限を取得する。

---

# 11. 外部サービス要件

MVPでは以下の外部サービスを利用する可能性がある。

## 11.1 地図サービス

目的地設定画面の地図表示に利用する。

採用サービスについて以下を確定する。

- サービス名称
- API
- 地図タイル提供元
- 利用料金
- APIリクエスト制限
- 利用規約
- ライセンス
- クレジット表記

## 11.2 地点検索サービス

目的地検索に利用する。

以下を確定する。

- 検索API
- 検索対象
- API利用制限
- 利用料金
- 利用規約
- ライセンス
- クレジット表記

## 11.3 経路探索サービス

MVPでは使用しない。

---

# 12. データ保存要件

MVPでは以下の方針とする。

### 保存するデータ

目的地設定に必要なデータのみを端末上に保持できる。

### 保存しないデータ

以下はMVPでは永続保存しない。

- 歩行軌跡
- 位置情報履歴
- 散歩履歴
- 過去の散歩距離
- 過去の散歩時間
- 過去の方角情報

MVPではサーバーへの位置情報送信を行わない。

---

# 13. プライバシー・セキュリティ要件

- 位置情報は距離・方角の算出に必要な範囲でのみ利用する。
- MVPでは位置情報をサーバーへ送信しない。
- 正確な位置情報をアプリケーションログへ出力しない。
- 開発・障害調査用ログに位置情報を含める場合は、位置を特定できない形式に加工する。
- ブラウザの位置情報権限状態を適切に処理する。
- 不要な位置情報を永続保存しない。

---

# 14. エラー・例外要件

## 14.1 位置情報権限拒否

以下を表示する。

- 位置情報が必要であること
- ブラウザまたは端末の設定から権限を変更できること
- 再試行方法

## 14.2 位置情報取得不能

以下を表示する。

- 現在地を取得できないこと
- 最終取得時刻
- 再取得を待機している状態

## 14.3 方位センサー利用不能

- 方位センサーを利用できない場合でも、目的地の方角情報を表示する。
- 矢印の表示方式を代替モードへ切り替える。

## 14.4 地点検索失敗

- 検索APIの通信失敗時にエラーを表示する。
- 検索結果が0件の場合、その旨を表示する。
- 地点検索が利用できない場合でも、地図上から地点を選択できる構成とする。

## 14.5 通信障害

案内画面では、距離・方角の計算に必要な位置情報を端末から取得できる場合、通信障害によってアプリ全体を停止しない。

MVPでは散歩データのサーバー同期を行わないため、通信障害による歩行ログ消失は発生しない。

---

# 15. 非機能要件

## 15.1 性能

- 新しい有効な位置情報を受信してから、距離・方角表示を原則1秒以内に更新する。
- UI操作に対して明らかな遅延が発生しないこと。
- 位置情報取得によるバッテリー消費を考慮する。
- 不要な外部API通信を行わない。

## 15.2 可用性

- 一時的な位置情報取得失敗によってアプリを終了させない。
- 一時的な通信障害によって案内画面を強制終了させない。
- 外部サービス障害時には、影響する機能のみを利用不能とする。

## 15.3 対応環境

- スマートフォン向けWebアプリとする。
- GPS等の位置情報取得に対応したモバイルブラウザを対象とする。
- 方位センサーを利用可能なモバイルブラウザを対象とする。
- 対象ブラウザおよびバージョンは開発開始時に確定する。

## 15.4 アクセシビリティ

- 方角や状態を色だけで表現しない。
- 方角は矢印と文字情報の両方で表示する。
- 屋外利用を考慮したコントラストを確保する。
- タップ対象には十分なタップ領域を確保する。
